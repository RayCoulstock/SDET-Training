# Phase 2 — Day 2 — Tea break 2 Menti

1. **How does a quality coach differ from a gatekeeper?**
   - A. The coach makes every release decision alone
   - **B. The coach helps the team reason about and own quality**
   - C. The coach avoids technical discussions
   - D. The coach writes all tests personally
   - Feedback: Coaching grows team capability rather than centralizing quality authority.

2. **Which code-review comment is most constructive?**
   - A. “This is bad.”
   - B. “Add tests.”
   - **C. “How will we control the clock to test the expiry boundary deterministically?”**
   - D. “I would have written it differently.”
   - Feedback: A specific question connects a risk to an actionable design concern.

3. **What should a quality-focused review prioritize?**
   - A. Personal formatting preferences only
   - **B. Risks, observable behaviour, failure modes, and testability**
   - C. Maximizing the number of comments
   - D. Replacing team conventions
   - Feedback: Review should improve confidence and shared understanding.

4. **When is the best time to raise a testability concern?**
   - A. Only after release
   - B. After a flaky suite has existed for months
   - **C. As early as the relevant design or code decision becomes visible**
   - D. Never during code review
   - Feedback: Early, specific collaboration gives the team more options.

5. **What makes feedback easier for a developer to act on?**
   - A. Assigning blame
   - **B. Explaining the risk, evidence, and a possible next step**
   - C. Withholding context
   - D. Requiring one exact implementation
   - Feedback: Evidence-based feedback supports collaboration and autonomy.
